## Key Concepts Summary

### OpenMP Directives Covered

| Directive | Purpose | Implicit Barrier | Use Case |
|-----------|---------|------------------|----------|
| `#pragma omp sections` | Divide work into sections | YES | Independent heterogeneous tasks |
| `#pragma omp section` | Define one section | - | One task within sections |
| `#pragma omp master` | Master thread only | NO | Master-specific I/O |
| `#pragma omp single` | Any one thread | YES | One-time initialization |
| `#pragma omp barrier` | Explicit sync point | N/A | Manual synchronization |
| `nowait` clause | Remove barrier | - | Optimize independent work |

### Synchronization Patterns

#### Pattern 1: Sections with Dependencies
```c
#pragma omp sections
{
    #pragma omp section
    {
        compute_A();
        mean = A_result;
        #pragma omp atomic write
        ready_flag = 1;
    }
    
    #pragma omp section
    {
        wait_for(ready_flag);
        compute_B_using(mean);
    }
}
```

#### Pattern 2: Master with Explicit Barrier
```c
#pragma omp parallel
{
    #pragma omp master
    { initialize(); }
    
    #pragma omp barrier  // CRITICAL!
    
    #pragma omp for
    for (...) use_initialized_data();
}
```

#### Pattern 3: Nowait Optimization
```c
#pragma omp parallel
{
    #pragma omp for schedule(static) nowait
    for (int i = 0; i < n; i++)
        array[i] = compute(i);
    
    // If array not used below, barrier is unnecessary
}
```

## Performance Tips

### Exercise 1: Sections Scalability
- ⚠️ Max threads = number of sections
- ✅ Use for heterogeneous tasks only
- ❌ Avoid for fine-grained parallelism

### Exercise 2: Amdahl's Law
- Serial portions limit speedup
- Formula: $S = \frac{1}{f_s + \frac{f_p}{p}}$
- Minimize serial work for better scaling

### Exercise 3: Load Balance
- Target efficiency > 90%
- Formula: $E = \frac{T_{avg}}{T_{max}}$
- Merge small tasks, split large tasks

### Exercise 4: Barrier Overhead
- Typical cost: 1-5% of runtime
- Use `nowait` when safe
- Profile before optimizing

## Common Mistakes & Solutions

### ❌ Mistake 1: Forgetting Barrier After Master
```c
#pragma omp master
{ init_data(); }
// Other threads race ahead ← BUG!
use_data();
```
✅ **Fix**: Add explicit barrier
```c
#pragma omp master
{ init_data(); }
#pragma omp barrier
use_data();
```

### ❌ Mistake 2: Too Many Sections
```c
#pragma omp sections
{
    #pragma omp section { task1(); }  // 50 sections
    #pragma omp section { task2(); }  // Only uses
    // ... 48 more sections           // 50 threads max!
}
```
✅ **Fix**: Use `parallel for` instead

### ❌ Mistake 3: Using Results Before Nowait Barrier
```c
#pragma omp for nowait
for (int i = 0; i < n; i++) A[i] = compute();

double sum = reduce(A);  // ← RACE! A[] incomplete
```
✅ **Fix**: Add barrier before using results
